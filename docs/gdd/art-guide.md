# Art Guide

[active] — the entry point for contributing art

The current art is placeholder-grade: every texture under `assets/textures/`
was generated by `ops/generate_placeholder_art.py`. Replace the files, keep
the names and sizes, and the game picks them up automatically.

## How art reaches the game

1. Content files in `content/` reference art by relative path:
   `sprite: Some("textures/ships/shuttle.png")` in a ship or planet
   definition (paths are relative to `assets/`).
2. Pack validation (`cargo test -p evr-data`) fails if a referenced file is
   missing — no dangling art references, ever.
3. The client loads the PNG at spawn. If a definition has no `sprite` field,
   the game falls back to a procedural shape, so content works before art
   exists.

## Conventions

| Kind | Path | Size | Notes |
|---|---|---|---|
| Ship | `assets/textures/ships/<ship-id>.png` | 128×128 | **Faces +x (east).** Draw in light/white — ships are tinted per faction (player cyan, pirate red) |
| Planet | `assets/textures/planets/<planet-id>.png` | 128×128 | Natural colors; no tint applied |

- RGBA PNG, transparent background
- Ship sprites render at ~30 px world size; planets at `radius * 2`
- File name should match the content id — makes replacement obvious

## Regenerating placeholders

```bash
python3 ops/generate_placeholder_art.py
```
